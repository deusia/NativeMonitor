# NativeMonitor

面向 Apple Silicon 的 macOS 菜单栏性能监控工具，使用 SwiftUI、AppKit 和系统计数器，在菜单栏查看实时读数，在概览与详情窗口查看趋势和分项数据。

> 项目仍处于原型阶段。GPU 驱动计数器、ANE 功耗和传感器依赖实验性数据源，兼容性随硬件和系统版本而异。

## 功能

- **菜单栏读数**：显示 CPU 使用率、内存用量和网络下载速率。
- **六类详情**：CPU、GPU、内存、磁盘、网络和传感器；支持分项曲线，网络区分上传与下载。
- **历史趋势**：可选 5 分钟、30 分钟、1 小时、6 小时或 24 小时范围，只展示本次启动后的真实样本。
- **可调采样**：支持 1、2、5 秒间隔，可调整 CPU 统计口径和读数小数位。
- **外观设置**：支持跟随系统、浅色和深色外观，可分区域调整背景效果，支持减少透明度和固定窗口。
- **本地运行**：不上传监控数据，无特权 helper；历史仅保存在内存中，退出后清空。

## 构建与运行

### 环境要求

| 项目 | 要求 |
| --- | --- |
| 硬件 | Apple Silicon Mac，仅构建 arm64 |
| 运行系统 | 最低部署版本为 macOS 14；macOS 26 及以上使用 Glass API |
| 开发工具 | Swift 6 工具链，以及包含 macOS 26 Glass API 的 Xcode SDK |

当前仅在开发机器的系统和 SDK 上验证，最低部署版本不代表已完成对应系统的兼容性验收。

### 使用 Xcode

1. 打开 `NativeMonitor.xcodeproj`，选择 `NativeMonitor` scheme 和 **My Mac**。
2. 按 **⌘R** 构建并运行；按 **⌘U** 运行测试。
3. 通过 **Product → Show Build Folder in Finder** 查找应用，构建产物位于 `Products/Debug` 或 `Products/Release`。

需要归档时，选择 **Product → Archive**，再通过 Organizer 的 **Distribute App** 导出；也可从归档的 `Products/Applications` 中取出 `.app`，复制到“应用程序”文件夹。

### 使用命令行

在仓库根目录执行：

```sh
# 运行测试
swift test

# 构建 Release 应用并进行本地 ad-hoc 签名
./build.sh

# 启动生成的应用
open ../NativeMonitor.app
```

脚本在仓库的上一级目录生成 `NativeMonitor.app`。Xcode 工程同样默认使用本地 ad-hoc 签名；向其他 Mac 分发时需自行配置 Apple Developer 签名和公证。

## 使用方式

启动后从菜单栏打开概览，进入详情查看各项指标。默认切换到其他应用时自动收起概览和详情；开启设置中的“固定窗口”后，失去焦点仍保持显示。固定窗口不代表置顶，仍可手动关闭。

| 操作 | 快捷键或入口 |
| --- | --- |
| 开关概览 | 点击菜单栏读数或 ⌘O |
| 关闭当前窗口 | Esc |
| 打开详情 | ⌘1 |
| 切换 CPU、GPU、内存、磁盘、网络、传感器 | ⌥⌘1～6 |
| 收起或展开详情侧栏 | ⌃⌘S |
| 退出 | ⌘Q |
| 调整采样、历史范围、CPU 口径、读数精度和外观 | 概览或详情中的设置按钮 |

设置自动保存在本机，仅影响本应用。详情窗口隐藏系统红黄绿按钮。

<details>
<summary>背景效果设置</summary>

在“设置 → 背景效果”中选择概览背景、详情背景、内容卡片或按钮与控件，可分别调整通透度（底色浓淡）、透明度（背景可见程度）和模糊度（0～30 pt）。调整实时生效，文字和图表保持清晰；支持恢复本区域或全部背景。

应用或系统开启“减少透明度”时优先使用普通背景，自定义数值会保留，关闭后恢复。系统管理的菜单、弹出框外壳及菜单栏由 macOS 决定材质。

</details>

## 监控指标

| 类型 | 主指标 | 其他参考指标 |
| --- | --- | --- |
| CPU | 全部逻辑核心的使用率之和（可切换为整机比例） | 各逻辑核心使用率、用户／系统／空闲；逻辑核心数、系统运行时间、1/5/15 分钟系统负载 |
| GPU | 驱动报告的设备利用率 | 渲染器、分块器利用率，驱动内存与核心数、设备名称、Metal 建议工作集、AI 加速能力及 ANE 平均功耗 |
| 内存 | 活跃、不可换出和压缩内存之和 | 物理内存、压缩、交换已用、活跃、非活跃、不可换出、空闲页和已用比例 |
| 磁盘 | 块存储设备读取速率 | 写入速率、设备累计读写、用户主目录所在卷总容量和可用容量 |
| 网络 | 运行中 `en` 接口的接收速率之和 | 发送速率、接口数量和名称、接口累计收发 |
| 传感器 | 可用的局部平均温度及风扇转速 | 原始温度、系统键名和测点分组，具体项目因机型而异 |

CPU、磁盘和网络速率需要两次采样，首次显示等待；采集失败时显示不可用并继续重试。部分指标与活动监视器采用不同口径，具体说明如下。

<details>
<summary>采样、历史与数值显示</summary>

每项展示本次运行期间、最多 30 分钟的样本平均值和峰值；图表可选择最多 5 分钟、30 分钟、1 小时、6 小时或 24 小时，只绘制启动后的真实样本；详情页提供分项曲线，缺失样本不会连接。图表仅对绘图点做峰谷压缩，概览小图最多 160 点，详情每条连续曲线最多 480 点，保留首尾和缺失断点；均值与峰值仍使用原始样本。均值为采样点的算术平均，不是时间加权平均。CPU、磁盘和网络速率需要两次采样，首次显示等待；计数器回退或网络接口变化时重新建立基线。采集失败时显示不可用，并清除对应曲线，后续继续重试。内存单位采用十进制 GB，速率按十进制自动选择 B/s、KB/s、MB/s 等单位；非零数值低于显示精度时显示为小于阈值。

系统指标、GPU 及传感器分别在后台采样，采样间隔可设为 1、2 或 5 秒；某一采样长时间阻塞时只报告一次超时，并不重复堆积请求；超时或停止后的迟到结果会被丢弃，过期或非有限读数不会写入历史，传感器连接失效后自动重建。系统读数按批更新界面，短时间范围通过二分查找截取历史，其他指标更新不会重新准备当前曲线；系统时间回拨时重新建立对应历史。历史仅保存在内存中，退出后消失。无网络上传或特权 helper。

</details>

<details>
<summary>CPU 与内存</summary>

CPU 详情根据系统的逻辑核心簇 ID 分组，默认折叠；簇总量为各核心使用率之和，平均值以簇内核心数归一化。无法读取完整簇拓扑时直接显示逻辑核心。CPU 核心类别通过系统拓扑及性能等级数量匹配推断；数量不唯一或信息不完整时使用中性色且不标注类别。M5 Max 的配色参考 Apple 官方芯片宣传图，紫色区分核心类别，并非 Apple 对各类核心指定的颜色。CPU 使用率来自各核心系统 CPU 时间差，用户时间包含 nice；核心总量口径下每个逻辑核心满载为 100%，例如 18 核的上限为 1800%；整机比例是各核心的平均值，上限为 100%。系统负载并非 CPU 百分比。

内存分项曲线展示活跃、非活跃、不可换出、压缩和空闲页；每张图的纵轴根据自身数据独立缩放，图形高度不能直接比较，各曲线也不能全部相加作为主指标。内存主指标不包括非活跃页，但活跃页可能包含文件缓存；该值不是应用内存或内存压力，与 `top`、活动监视器的已用内存口径不同。

</details>

<details>
<summary>GPU 与 ANE（实验性）</summary>

GPU 字段来自 IORegistry 的 `IOAccelerator` / `PerformanceStatistics`，只接受单个 AGX 驱动；字段与统计窗口没有稳定的公开契约，不是进程 GPU 时间，渲染器和分块器利用率不能相加；驱动的系统内存统计不等于独立显存，Metal 建议工作集不等于实际占用。Metal Apple10 及以上 GPU 的每核心 Neural Accelerator 与独立 Apple Neural Engine 是不同硬件；本应用目前无法获取两者的独立实时利用率，不以 GPU 总利用率代替。GPU 详情中的 ANE 平均功耗来自私有 IOReport 能量模型，以驱动发布时间计算最近一次发布区间的平均值；目前仅识别单个 `ANE0`，首次采样、数据停更或格式不兼容时显示不可用。功耗不等于利用率，也未经过外部功率仪校准。GPU 核心数按实验性驱动 `core_mask_list` 中置位数计算，`num_cores` 不作为实际启用核心数；缺少完整掩码时显示不可用。

</details>

<details>
<summary>磁盘与网络</summary>

磁盘速率为系统识别的块存储设备之和，可能包含外接设备；容量属于主目录卷，受 APFS 共享空间影响。

网络统计使用 64 位接口计数器，包含局域网流量，只选择名称以 `en` 开头且处于运行状态的接口，不包含 VPN 等其他接口；多个接口的统计也可能受系统拓扑影响，不等于互联网流量。

</details>

<details>
<summary>温度与风扇传感器（实验性）</summary>

传感器详情优先展示风扇转速及局部平均温度，原始温度默认收起并按系统键名前缀分组。M5 系列的 CPU、GPU 测点名称参考 [Stats](https://github.com/exelban/stats/blob/master/Modules/Sensors/values.swift)，分别对可用的对应测点等权平均，排除不大于 0°C 或高于 110°C 的读数；该值并非整机温度，也不是最高温度。映射并非 Apple 官方定义，其他机型暂不计算平均值，未识别的键保留原名，前缀不代表确定的硬件部件。读数来自 AppleSMC；可读取的项目因机型和系统版本而异，无风扇设备可能没有转速。AppleSMC 为私有接口，不支持的读数不会展示，接口不可用时显示提示。

电池、无线和存储的部分键名参考 [VirtualSMC](https://github.com/acidanthera/VirtualSMC/blob/master/Docs/SMCSensorKeys.txt) 与 [MacMonitor](https://github.com/ryyansafar/MacMonitor/blob/main/SENSORS.md)，属于跨机型参考而非 M5 Max 的官方位置说明。核心簇测点不一定对应单个核心；附近测点不一定是部件内部温度。无法识别的键标为“部件未知”。

</details>
